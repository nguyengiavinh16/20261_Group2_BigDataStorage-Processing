Real-Time Detection Report

Streaming MVP, historical replay and handoff · 21 November 2026

The local detector replayed a labeled GVT/BTC pump through Kafka, PyFlink and Redis. Both runs produced 1,962 feature records and four alerts from 11,340 trades. The MVP code is committed through M12 (355ae7d). Cluster recovery and team integration checks remain open.

1. Implementation

ModuleBehavior
M01-M03 · InputTest fixtures cover the offline flow. The job reads live or scoped replay Kafka input, validates canonical trades and deduplicates trade IDs.
M04-M06 · FeaturesEvent-time tumbling windows compute 60-second features by venue and for ALL. Redis baselines supply volume z-scores, with an EMA fallback when available.
M07-M09 · AlertsVersioned pump and dump rules attach risk and reasons. Keyed state links both phases under one case per venue. Kafka carries features, alerts and live dead-letter records.
M10-M12 · OperationsPrometheus metrics expose latency, late events and baseline issues. Separate live and replay manifests configure checkpoints. The HTML demo presents measured Kafka output and run evidence.

4. Local detector performance (O1 and O8)

A synthetic live burst sent 569 trades across nine symbols into local Kafka and Flink 1.20.5 with Redis, one subtask and a five-second watermark. It produced 16 schema-valid alerts. The observed burst input rate was 370.3 messages/s, peak sampled backpressure was 0 ms/s and consumer lag returned to zero after checkpointing.
