# ADR-0005: Iceberg tables with a JDBC (Postgres) catalog

- Status: Accepted
- Date: 2026-11-16

## Context
Silver/Gold need ACID MERGE (idempotent re-runs), schema evolution, partitioning and time travel on object storage.
A catalog is required. Options: Hive Metastore, Nessie, Iceberg REST catalog, JDBC catalog.

## Decision
**Apache Iceberg** with the **JDBC catalog** stored in the shared Postgres (`iceberg_catalog` DB), named `cg`,
namespaces `silver` and `gold`. Spark config is generated by `cg_batch.spark_session.spark_conf`.

## Consequences
- + One fewer service (Postgres already exists for Airflow and MLflow); works the same locally and on GCP.
- + Trino can read the same catalog (iceberg connector, catalog type jdbc) for dashboards.
- − No multi-table transactions/branching (not needed). Revisit with a REST catalog if multiple engines conflict.
